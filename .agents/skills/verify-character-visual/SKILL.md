# キャラクターの見た目を実画面で検証する

投影とリップシンクは**数値が正しくても見た目が破綻する**種類の処理。テストが通ったことを完了条件にしない。

## 先に数値で見る

実画面の確認は高コストなので、先に安い検査を通す。

- 投影の**書き込み画素数**と**書き込み領域のバウンディングボックス**が想定内か
- 6表情 × 6母音の枚数が揃っているか
- 画像の寸法とアルファチャンネルが期待どおりか（キャプチャ1024²、アトラス2048²）

ここで異常が出たら実画面を見る前に直す。

## 透過を確認する

**四隅のアルファ値だけで合格にしない。** 透過市松または透明な画面で実表示を確認する。

見るもの:

- **ハロー**（輪郭の白or黒フチ）— 背景除去の消し残しと誤認される。出ていたら不合格
- **矩形の縁**（切り出し範囲の直線が見える）
- **色面**（本来透明な領域にうっすら色が乗る）
- **太い外周影**

意図した背景が必要な場合は、キャラクター画像側に焼き込まず**画面側の明示的な背景レイヤー**で出す。

## フェイスパッチ投影を確認する

生成直後に必ず見る。破綻パターンは決まっている。

| 症状 | 原因 |
|---|---|
| 顔が**後頭部や髪の裏**にも出ている | レイキャストの最前面判定が効いていない |
| 顔が**体や別パーツ**に出ている | 頭ボーンのウェイト閾値で三角形を絞れていない |
| 顔が**ずれている・縮んでいる** | キャプチャフレームとメッシュのポーズが不一致。中立スナップショットを使っていない可能性 |
| 顔に**細い隙間の格子**が見える | UV継ぎ目の膨張が足りない |
| 顔の周囲に**他パーツの色が滲む** | 継ぎ目膨張が非採用三角形のUV領域を避けていない |
| **表情が変わって見えない** | 差分マスクが厳しすぎる、または投影画素がほぼ0 |
| **顔全体が変わってしまう**（髪型・色が違う） | 画像生成側のドリフト。差分マスクが緩い |
| **左右が反転している** | 画像生成側のミラーリング。プロンプトの反転禁止が効いていない |

正面だけでなく**斜め・横からも見る**。正面だけだと貫通と位置ずれを見落とす。

## 表情と母音の切り替わりを確認する

- 6表情がそれぞれ区別できるか
- **母音が区別できるか。** 特に `i` と `e`、`u` と `o` は潰れやすい
- 切り替わりに引っかかりや一瞬の白抜けが無いか
- 無音時に口が閉じるか

リップシンクは**合成した母音音声（既知のフォルマント）で先に検査**し、実マイクでの確認は最後に1回でよい。

## OBS出力を確認する

- ブラウザで開いて**背景が透過**しているか（`body` に不透明な背景が付いていないか）
- WebSocket の状態更新（表情・口形）が反映されるか
- ウィンドウサイズを変えて描画が追従するか
- 本体プレビューと OBS ページで**同じ描画コードを共有**しているか。二重実装になっていないか

OBS 実機での最終確認は利用者に委ねてよい。

## 後始末

- 確認用に起動したプロセス・ブラウザ・推論エンジンは止める
- **プロセスを止める前に、親プロセスとコマンドラインで「自分が起動したもの」か確かめる。** 名前だけで一括終了しない
- 撮影した画像・連番フレームは `temp/` にだけ置き、コミットに含めない
- three.js のジオメトリ・マテリアル・テクスチャを `dispose()` しているか、キャラ切り替えを数回繰り返してメモリが増え続けないか確認する

## 報告

見た目の最終判断は利用者に委ねてよい。ただし**何をどの角度で確認し、どの症状が出ていないと言えるか**を具体的に書く。「問題なし」だけで済ませない。
