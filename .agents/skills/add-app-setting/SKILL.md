# 設定項目を追加・変更する

設定は**実装と文書が片方だけ更新されて壊れる**代表格。追加・変更・削除のどれでも、この手順を最後まで通す。

## 調べる

先に既存を確認する。**似た設定が既にあるなら新設せず既存へ寄せる。**

- `src-tauri/src/config.rs`（設定の正本）
- `docs/SETTINGS.md`（設定キー一覧の正本）
- 変更対象の値がソースへ直接書かれていないか（ハードコードの取り残し）

## 決める

- **キー名** — 既存の命名に合わせる。区分（`pipeline.` / `facepatch.` / `lipsync.` / `vad.` / `obs.` / `ai.` / `display.`）を先頭に付ける
- **型と既定値** — 既定値は「何も設定しない利用者にとって妥当な値」にする
- **環境変数名** — 接頭辞を付ける。**環境変数を正本・保存先にしない**（既定値の上書き手段としてのみ）

優先順位は必ず **永続ファイル（`app_config_dir/config.json`） > 環境変数 > ハードコード既定値**。

## 実装する

- 値は**都度読む**（`cfg.get(キー, 既定値)`）。起動時に読んで持ち回らない。設定画面で変更したら再起動なしで反映されるようにする
- **同じ値をソースの複数箇所へ書かない。** 閾値・パス・モデル名・解像度はすべて設定から引く
- 設定画面へ項目を出す。設定画面が唯一のGUI設定入口
- 保存は**原子的に**行う（一時ファイル → `sync_all` → `rename`）。直接上書きしない
- 「読む → 直す → 書き戻す」はロックを取ってから行う

## 秘密値を扱う場合

本プロジェクトは製品からクラウドAPIを呼ばないため、**通常は秘密値の設定を作らない**。どうしても必要になった場合のみ:

- キー名に `API_KEY` / `TOKEN` / `SECRET` / `PASSWORD` / `CREDENTIAL` のいずれかを含める
- スキーマで `type="password"` を申告する
- **平文で `config.json` に置かない。** OS の資格情報保護へ預ける
- ログ・エラーメッセージ・ドキュメント・PR本文へ値を出さない。認証ヘッダをエラー文へ連結しない

## 文書を更新する（同じ作業内で）

| 内容 | 書く場所 |
|---|---|
| **全設定キー**（キー名・型・既定値・説明） | `docs/SETTINGS.md`（**正本**） |
| 設定の保存・反映機構が変わった場合 | `SPEC.md` |
| 利用者がよく使う項目だけの説明 | `README.md`。**全キーを複製しない** |

`docs/SETTINGS.md` の記載漏れ・削除漏れは**実装と双方向で検出するテスト**が拾う。手作業の突き合わせをしない代わりに、**テストを通してから完了とする。**

設定キーでない文字列がテストに引っかかった場合は、理由を書いて除外リストへ入れる。テストを緩めない。

## 削除する場合

- 実装・設定画面・`docs/SETTINGS.md` の3箇所から消す
- **既存の `config.json` に残った古いキーで起動が壊れないこと**を確認する。未知のキーは無視して継続する
- 消したキーと理由を PR 本文へ書く

## 完了条件

- `cargo test --lib` が通る（双方向同期テストを含む）
- 設定画面から変更して**再起動なしで反映される**
- `docs/SETTINGS.md` と実装が一致している
