# キャラクター生成パイプラインを実行する

## 正規入口

仕様は SPEC.md 4.2 に照合し、アプリの PipelineContext を経由する。

```powershell
cargo run -p local-vtuber-studio --bin pipeline-probe -- <input.png> <id> <identity-tags>
cargo run -p local-vtuber-studio --bin pipeline-probe -- --only <characterId> <stage>
cargo run -p local-vtuber-studio --bin pipeline-probe -- --resume <characterId> <stage>
```

- 工程を isolate → decompose → rig2d の順に実行し、前段をディスクへ確定してから次へ進む。
- source/input.png は上書き・削除しない。
- isolate は元のキャンバスを保つ。入力に明示された透過があれば保持し、不透明画像には背景除去を実行する。
- decompose は承認済み固定版Grounding DINO baseで意味領域を検出し、SAM 2.1 Hiera Tinyで原寸マスクを求める。`cargo xtask setup grounding`で取得し、モデルを逐次ロードする。未検出を固定座標で補わない。analysis.jsonに候補と選別結果を保存する。
- 目のSAM局所ROIはai.eye_context_marginから求める。解析署名の版2とsampling_regionを確認し、余白変更後に旧マスクを再利用しない。原寸のまつげ・髪・肌の境界を比較する。
- rig2d は版2 manifestの座標と差分を lvs-anime25d-v1 の版3リグへ引き継ぐ。必須中立画像、実測座標、原寸で切詰めたtexture_boxを確認する。版2リグは再生成する。
- 唇の分割にはmouth_closed.lip_seamとlip_rig_version: 1が必要。旧リグはdecomposeから再生成する。原画の唇は拡大素材や塗り直した色面へ差し替えず、上下メッシュの中立座標が原画と一致することを検査する。
- 目にはeye_rig_version: 3、左右のeye_base/eyelid_upperとeye_aperture、eye_iris/eye_remainder/eye_backplateが必要。相補分割と白目補完の可視画素保持を検査する。旧リグはdecomposeから再生成する。
- scene_graph_version: 1の独立素材と親子関係を検査する。表情領域が顔に含まれ、元の目が未分類素材に残らないことを閉眼表示で検証する。所有画素の完全被覆と隠れ領域の補完を混同しない。
- rig2d のコピー前検査でPNG/RGBA、原寸キャンバス、非空アルファ、部位名の重複、格納先、bbox・pivot・重なり順を検証する。メタデータの充足や候補スコアを見た目の合格に代用しない。
- 切詰めPNGの透明RGB補完を変えた場合はrig2dを再実行する。可視RGBAと全アルファの一致、原寸の維持、縮小描画の暗い縁を検証する。
- モデル候補を独断で変更しない。旧3D工程へ戻さない。
- 診断用の個別スクリプト出力を製品成果物へ昇格しない。
- GPU生成は1件ずつ行い、比較診断も同時実行しない。

## 再実行と診断

入力を変えたら新キャラとして全工程を実行する。部位分類・目口検出・差分生成を変えたら decompose 以降を、リグ定義だけなら rig2d を再実行する。古いリグが新方式へ黙って混在しないよう形式版を検証する。

再実行前に旧成果物を削除しない。分解・リグの正規入口はoutput_transactionで生成・公開を保護する。出力先の親のtemp/にあるpending/previousを手作業で消さず、次回の同じ工程の開始時に復旧させる。生成失敗、公開rename失敗、中断後の復旧をsidecar/test_output_transaction.pyで検査する。二段階renameは表示読者まで保護する原子的な世代切替ではないため、同時読み込みの保証を主張しない。

意味解析はanalysis/に署名とマスクを保存する。入力画素・モデル・解析コード・閾値・依存版が一致する場合だけ再利用し、差分補完のみの再実行ではGPU解析を重複させない。キャッシュのハッシュと寸法を検査し、不正データを成功扱いしない。

一時診断は temp/ に限る。候補マスクの診断だけは decompose の --keep-candidates を使ってよいが、その出力を完成品にしない。SAM候補の有無と、部位名への割り当ての失敗を区別する。

利用者が承認した意味解析の比較は `tools/semantic-eval/` を使い、docs/DEVELOPMENT.mdの「意味解析候補の比較」に従う。これは製品の正規入口ではない。原画と診断出力をtemp/に限定し、全身/頭部・原画間で同じ語句と選別規則を使う。モデルによる候補の返却順や信頼度の有無を混同せず、誤検出・欠落も保存する。モデル同士のマスク一致率は正解率ではない。

## 承認済みQwenの補完比較

Qwen-Image-LayeredとQwen-Image-Edit-2511の比較には`tools/qwen-eval/`を使い、docs/DEVELOPMENT.mdの比較手順へ従う。比較承認と製品採用を区別する。models.jsonの固定SHA検査を飛ばさず、API/カスタムノードを無効化した本アプリ管理ComfyUIで逐次実行する。原画・正規出力は上書きしない。頭の原寸ROIと全身縮小を混同せず、拡大した素材を完成品へ採用しない。Layeredの0枚目は全体再生成であり、独立部位数へ数えない。全体画像と残りのRGBAレイヤーの合成を比較し、顔立ち・首/襟・透過・隠れ領域を実画像で確認する。失敗はreport.jsonと実行出力に残す。

## 比較結果を動作画面で評価する場合

利用者が動作評価を承認したら`tools/qwen-eval/build_preview.py`とDEVELOPMENT.mdの比較手順を使う。既存キャラを上書きせず別IDにし、製品へ採用したと扱わない。補完を不透明な遮蔽の下だけに限定し、中立の既存合成とRGBAが一致することを公開前に検査する。原画/解析・原リグ全素材・生成画像のSHAを公開前に再照合する。髪だけの局所相対移動と全身の独立関節化を混同しない。同じcheck.htmlで補完オン/オフ、元キャラへの切替、口と閉眼を実表示で比較する。

横髪用比較を併用する場合は`--side-comparison`とDEVELOPMENT.mdの比較仕様版19手順を使う。生成済み画像の原寸・原画/解析の同一性と公開前SHAを検査する。可視の耳輪郭を変える`--redraw-ear-contour`は利用者の承認を得た場合だけ使う。生成画像と原画の耳をそれぞれ既存DINO/SAMで抽出し、色差だけで耳全体の範囲を代用しない。原画ファイル・目口・許可領域外の画素を保持する検査を通す。輪郭修正版では中立も変わるため、原画全画素固定と呼ばない。通常の非描き直し比較は中立RGBA一致を必須とする。

閉眼の比較は`tools/qwen-eval/build_eye_preview.py`とDEVELOPMENT.mdの手順を使う。同一原画の入力4SHA、原寸で完了した編集、親リグの署名を照合する。まぶたの透過素材だけを抽出し、肌・口などを生成画像ごと貼らない。測定不能を固定曲線で代用しない。原画・他素材を保持して別IDへ公開し、左右別に開き0/0.5/1と連続まばたき・口パクを検証する。個別候補の見た目承認をモデル採用や別原画の合格へ広げない。

## 停止条件

入力の前景が空、顔・髪・胴体が識別不能、目口を測定できない、必須画像・座標が欠落、キャンバス寸法が不一致なら明示エラーで止める。固定位置を黙って補って成功扱いしない。

## 再現性と見た目

- 同じ入力の反復で同じ座標・画素が得られるか検査する。
- 合成fixtureでは平行移動・余白変更の影響を検査する。
- 実写だけで完了にせず、女性A・むぎ等の別原画を同じ工程で検証する。
- verify-character-visual を読み、閉口、開口、閉眼、小角度変形、透過と原画保持を実ブラウザで比較する。
- テスト成功と目視合格を分けて報告する。未達の画風・入力条件は TASKS と PR 本文へ残す。
- 終了時は自分のプロセスと確認タブを閉じる。停止前に親PIDとコマンドラインを照合する。
