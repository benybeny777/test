# キャラクター生成パイプラインを実行する

**工程順を誤ると成果物が壊れる。** 各工程は前段の出力に依存する。必ず権利確認済みの固定版だけを使い、次の順で実行する。

仕様は [SPEC.md](../../../SPEC.md) 4.2〜4.4。

## 正規の入口

生成は必ずアプリのパイプライン経由で行う。個別スクリプトや別リポジトリの一時ファイルを製品成果物にしない。

既定工程は次とする。

```
① isolate     source/input.png → source/isolated.png
② decompose   isolated.png     → layers/source.psd + manifest.json + parts/*.png
③ rig2d       source.psd       → rig2d/rig.json + rig2d/parts/*.png
```

- `source/input.png` は上書き・削除しない
- ②は固定版SAM 2.1 Hiera Tinyで候補マスクを生成し、製品内の決定的処理で意味付けする
- SAM 2を意味分類器として扱わず、位置・包含・接続・入力シルエットとの関係をmanifestへ記録する
- ③は本製品固有の `lvs-anime25d-v1` を出力し、PicoAgentやLive2D/Cubismの形式を正本にしない
- 閉口、開口、左右の目、顔、前後髪、胴体の必須パーツが欠けたら明示エラーにする
- 原画とパーツを補間で引き伸ばさない

## 廃止した旧3D試作の記録

旧コードでは `mesh` が①と②を連続実行し、以降は `rig`、`capture`、`expression`、`facepatch` の5工程として表示していた。品質不合格のため再利用せず、新しい完成経路へ戻さない。

```powershell
cargo run -p local-vtuber-studio --bin pipeline-probe -- <input.png> <id> <identity-tags>
cargo run -p local-vtuber-studio --bin pipeline-probe -- --only <characterId> <stage>
```

## 工程と依存

```
① 背景除去        source/input.png      → source/isolated.png
② 画像→3D        isolated.png          → model/mesh.glb
③ リギング        mesh.glb              → model/rigged.vrm
④ 中立キャプチャ   rigged.vrm            → facepatch/neutral.png + capture_frame.json
⑤ 表情・母音生成   neutral.png           → facepatch/expr/*.png
⑥ 逆投影          rigged.vrm + expr/*   → facepatch/projected/*.png
```

**各工程の成果物をディスクへ保存してから次へ進む。** メモリ上だけで繋がない。途中再開ができなくなる。

## 絶対に守ること

- **入力イラストの原本 `source/input.png` を上書き・削除しない。** すべての再生成はここを起点にする
- **④の中立キャプチャは、スキニング済みメッシュのスナップショットを保存する。** ⑥の投影は必ずそのスナップショットを使う。現在ポーズで投影すると、ポーズが変わるたび結果がずれる
- **③のリグが変わったら④以降を全部やり直す。** キャプチャフレームはボーン位置に依存している
- **⑤のプロンプトを変えたら⑥をやり直す。** プロンプトは署名に含まれる
- 任意表情はアプリで定義を追加してから⑤を再実行する。`e_<プロンプトSHA-256先頭8桁>` 以外のキーを生成スクリプトへ渡さない
- **⑥の書き込み画素が0なら失敗。** 空のテクスチャを保存して先へ進めない

## 再実行の判断

やり直す範囲は署名で決まる。**手で「たぶん大丈夫」と判断しない。**

| 変えたもの | やり直す工程 |
|---|---|
| 入力イラスト | ①から全部 |
| 画像→3D のモデル・パラメータ | ②から |
| リギング | ③から |
| キャプチャ解像度・顔矩形 | ④から |
| 表情プロンプト・画像生成モデル・denoise | ⑤から（該当表情のみ可） |
| 投影パラメータ（差分閾値・法線閾値・継ぎ目膨張など） | ⑥のみ |

署名が一致すればキャッシュを使い、一致しなければ再計算する。**署名に含める値を増やしたらパイプライン版番号を上げる**（`facepatch.pipeline_version`）。上げ忘れると古いキャッシュを新しいパイプラインで使い回して破綻する。

## 失敗したときに止まる条件

次はすべて**明示エラーにして止める**。崩れた成果物を先へ流さない。

- ②で人型として成立しないメッシュが出た
- ③で A/T ポーズ以外と判定された、または標準ヒューマノイドボーンが揃わなかった
- ④で頭ボーンが見つからなかった
- ⑤でComfyUIが失敗した、出力が欠けた、または1024x1024ではなかった
- ⑥で投影画素が0、または採用三角形が0

⑥が失敗したら**診断画像（採用三角形マスク・元画像マスク・書き込み領域）を保存する。** これが無いと原因の切り分けができない。

## 実行後に確認すること

- 投影画素数と書き込み領域のバウンディングボックスが想定内か
- 組み込み5表情なら30組、任意表情N件を含むなら `(5+N)×6` 組が揃っているか
- 実際にモデルへ適用して、顔が正しい位置に貼られているか（[verify-character-visual](../verify-character-visual/SKILL.md) を使う）
- 外部PNGをThree.jsへ渡すとき `flipY=false` か。VRMでは `true` にするとUVアイランドが上下反転する

## コスト

生成の実走は数分かかり GPU を占有する。**パラメータを変えるたびに全工程を回さない。** 変更が出揃ってから、影響する工程だけを最小回数実行する（[AGENTS.md](../../../AGENTS.md)）。

終わったら子プロセス（Python サイドカー、推論エンジン）を `kill` して `wait` でハンドルまで回収する。ゾンビを残すと次回の生成が失敗する。
