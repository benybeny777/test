# キャラクター生成パイプラインを実行する

## 正規入口

仕様は SPEC.md 4.2 に照合し、アプリの PipelineContext を経由する。

利用者が既存キャラを指定した場合は、元プロジェクトのキャラID・入力パス・原画SHAを照合する。「実写テスト」などの同じ表示名だけで手元の別素材へ置き換えない。照合結果と採用入力をPR本文へ記録する。

```powershell
cargo run -p local-vtuber-studio --bin pipeline-probe -- <input.png> <id> <identity-tags>
cargo run -p local-vtuber-studio --bin pipeline-probe -- --only <characterId> <stage>
cargo run -p local-vtuber-studio --bin pipeline-probe -- --resume <characterId> <stage>
```

- 工程を isolate → decompose → rig2d → complete の順に実行し、前段をディスクへ確定してから次へ進む。
- source/input.png は上書き・削除しない。
- isolate は元のキャンバスを保つ。入力に明示された透過があれば保持し、不透明画像には背景除去を実行する。
- decompose は承認済み固定版Grounding DINO baseで意味領域を検出し、SAM 2.1 Hiera Tinyで原寸マスクを求める。`cargo xtask setup grounding`で取得し、モデルを逐次ロードする。未検出を固定座標で補わない。analysis.jsonに候補と選別結果を保存する。
- 目のSAM局所ROIはai.eye_context_marginから求める。袖・手の問い合わせを含む解析署名の版3とsampling_regionを確認し、余白変更後に旧マスクを再利用しない。原寸のまつげ・髪・肌の境界を比較する。
- rig2d は版2 manifestの座標と差分を lvs-anime25d-v1 の版3リグへ引き継ぐ。必須中立画像、実測座標、原寸で切詰めたtexture_boxを確認する。版2リグは再生成する。
- rig2dの出力先はrig2d-base/とし、未補完リグを完成扱いしない。completeで利用者採用承認済みQwen-Image-Edit-2511を管理下ComfyUIで実行し、原寸の閉眼・隠れ顔・耳を別々の局所マスクで編集してrig-generations/g_<ID>/へ保存しrig-current.jsonで公開する。DINO/SAMと承認済みの口は維持し、Layeredや別モデルへ無断変更しない。
- completeはsidecar/completion/generate.pyをRust経由で呼び、ai.completion_*と既存comfy設定を次回処理時に読む。モデル固定SHA、マスク外画素保持、入力原画/解析/基底リグの公開前SHAを検査する。completion-sourceの生成署名と完成completion.jsonの抽出署名を分け、抽出だけの変更でGPUを再実行しない。入力準備・推論の意味を変えたらIMAGE_GENERATION_VERSIONを上げる。出力欠損・改変は失敗にする。
- 閉眼だけだった旧通常4工程は3原画で実走済みだが、追加の隠れ顔/耳を含む現行版の実走・目視とは分けて記録する。生成版2のマスクは目コアを255とし、髪は0、減衰は外側余白だけにする。髪際のまつげを弱編集して旧線を残さないよう、実マスクのコア強度と生成画像の残片を検査する。
- 最終補完版4では閉眼に加えて原画耳解析→隠れ顔/横髪耳の原寸マスク編集→生成耳解析→素材組立を逐次実行する。画像生成とDINO/SAMを同時ロードしない。各画像と耳マスクを独立署名で再利用し、マスク外・目口・原画アルファ・耳許可外RGBを保持する。原画と生成画の両方で測定できた耳側だけを補修し、未測定側は原画輪郭を保持してpartial警告を出す。生成耳が両側とも無い場合は明示失敗する。閉眼のみの実走時間/品質を追加2編集の成功根拠にしない。
- 閉眼生成版5ではmask_core_ratioを署名へ含め、左目、右目の順に同じ原寸画像へ局所編集を重ねる。両目同時編集や左右別生成後の合成へ戻さない。既存mask0と外縁を保持したまま内側の編集強度を比較する。隠れ顔のマスク版3は抽出と共通の肌支持帯と限定境界だけを編集し、髪全体へ別の顔を生成させない。横髪・耳は版2を維持する。再分類の比較参照は白合成入力とし、半透明の未編集画素を編集差と誤認しない。旧成果と新条件の実走を区別する。
- 耳の可視補修で髪全体の所有を解除しない。原画耳の実測輪郭と生成耳の交差だけを露出し、その他の生成耳は原画髪の下に保持する。alpha254と255の中立合成、平行移動・左右反転、小角度で矩形や巨大な耳が露出しないことを検査する。
- 唇の分割にはmouth_closed.lip_seamとlip_rig_version: 1が必要。旧リグはdecomposeから再生成する。原画の唇は拡大素材や塗り直した色面へ差し替えず、上下メッシュの中立座標が原画と一致することを検査する。
- 目にはeye_rig_version: 3、左右のeye_base/eyelid_upperとeye_aperture、eye_iris/eye_remainder/eye_backplateが必要。相補分割と白目補完の可視画素保持を検査する。旧リグはdecomposeから再生成する。
- scene_graph_version: 1の独立素材と親子関係を検査する。表情領域が顔に含まれ、元の目が未分類素材に残らないことを閉眼表示で検証する。所有画素の完全被覆と隠れ領域の補完を混同しない。
- 検出済みの襟は任意scene_collarへ移管し、首より前・顔より後、parent=torsoを確認する。位置・幅フィルタ後に信頼度を優先し、低信頼度の小さな断片を最小面積だけで選ばない。中立RGBAを保持し、未検出/完全遮蔽なら空素材を増やさない。旧出力はdecomposeから再生成して反映する。

- 袖・手の任意分割は解析版3で再解析する。DINO/SAMの候補と不採用理由、manifestのmaterial_status.optional_limbsを照合する。可視所有は同側の腕からだけ移管し、曖昧候補や親腕消失を成功扱いしない。scene_sleeve/handの親腕継承を確認し、独立関節や隠れ素材完成と呼ばない。
- rig2d のコピー前検査でPNG/RGBA、原寸キャンバス、非空アルファ、部位名の重複、格納先、bbox・pivot・重なり順を検証する。メタデータの充足や候補スコアを見た目の合格に代用しない。
- 切詰めPNGの透明RGB補完を変えた場合はrig2dを再実行する。可視RGBAと全アルファの一致、原寸の維持、縮小描画の暗い縁を検証する。
- モデル候補を独断で変更しない。旧3D工程へ戻さない。
- 診断用の個別スクリプト出力を製品成果物へ昇格しない。
- GPU生成は1件ずつ行い、比較診断も同時実行しない。
- 長時間の補完実走中は対象の入力4ファイル、基底リグ、署名対象のcompletion非テストPythonを変更しない。公開前の変更検査で正しく失敗するため、修正はtemp内の独立コピーとCPU検査で準備し、実走終了後に適用する。検査を外して途中変更を通さない。

## 再実行と診断

入力を変えたら新キャラとして全工程を実行する。部位分類・目口検出・差分生成を変えたら decompose 以降を、リグ定義だけなら rig2d 以降を、局所補完条件だけなら complete を再実行する。古いリグが新方式へ黙って混在しないよう形式版と補完署名を検証する。

再実行前に旧成果物を削除しない。分解・基底リグ・rawはoutput_transactionで保護し、pending/previousを手動削除せず同じ工程の再開で復旧させる。最終リグは別契約のreference_storeで不変世代へ公開し、rig-current.jsonを原子的に置換する。current・previous・生存読者のOS leaseを保持する世代回収を壊さない。旧比較rig2dを移動/削除/新世代への直接採用しない。Windows起動時の最終参照回収・legacy復旧を全工程の起動時復旧と呼ばない。

意味解析はanalysis/に署名とマスクを保存し、入力画素・モデル・解析コード・閾値・依存版の一致時だけ再利用する。3raw編集は解析キャッシュとは別に、原画2SHA・実入力PNG/マスク・ROI・全推論条件の完全一致を確認する。解析2SHAだけの変更でrawを再推論しないが、元manifest全バイトと実生成出自は保持する。現在source4と原raw出自を最終版4へ分けて記録し、RawLeaseの画像/manifest SHAと公開前source/base/codeガードを必ず維持する。既知旧eye1/2/3/4・隠れ顔mask1/2・横髪耳mask1は検証後再生成、未知版と破損は拒否する。

一時診断は temp/ に限る。候補マスクの診断だけは decompose の --keep-candidates を使ってよいが、その出力を完成品にしない。SAM候補の有無と、部位名への割り当ての失敗を区別する。

利用者が承認した意味解析の比較は `tools/semantic-eval/` を使い、docs/DEVELOPMENT.mdの「意味解析候補の比較」に従う。これは製品の正規入口ではない。原画と診断出力をtemp/に限定し、全身/頭部・原画間で同じ語句と選別規則を使う。モデルによる候補の返却順や信頼度の有無を混同せず、誤検出・欠落も保存する。モデル同士のマスク一致率は正解率ではない。

## 承認済みQwenの補完比較

Qwen-Image-LayeredとQwen-Image-Edit-2511の比較には`tools/qwen-eval/`を使い、docs/DEVELOPMENT.mdの比較手順へ従う。比較承認と製品採用を区別する。models.jsonの固定SHA検査を飛ばさず、API/カスタムノードを無効化した本アプリ管理ComfyUIで逐次実行する。原画・正規出力は上書きしない。頭の原寸ROIと全身縮小を混同せず、拡大した素材を完成品へ採用しない。Layeredの0枚目は全体再生成であり、独立部位数へ数えない。全体画像と残りのRGBAレイヤーの合成を比較し、顔立ち・首/襟・透過・隠れ領域を実画像で確認する。失敗はreport.jsonと実行出力に残す。

## 比較結果を動作画面で評価する場合

固定頭部範囲に全身が入る原画では、DEVELOPMENT.mdの`--head-framing measured`を比較し、顔の原寸画素を保った頭部切り出しにする。生成後の拡大・位置変更を見逃して元の座標へ貼らない。閉眼線が元の領域で測れない出力は失敗として保持し、固定座標や引き伸ばしで成功へ変えない。

利用者が動作評価を承認したら`tools/qwen-eval/build_preview.py`とDEVELOPMENT.mdの比較手順を使う。既存キャラを上書きせず別IDにし、製品へ採用したと扱わない。補完を不透明な遮蔽の下だけに限定し、中立の既存合成とRGBAが一致することを公開前に検査する。原画/解析・原リグ全素材・生成画像のSHAを公開前に再照合する。髪だけの局所相対移動と全身の独立関節化を混同しない。同じcheck.htmlで補完オン/オフ、元キャラへの切替、口と閉眼を実表示で比較する。

横髪用比較を併用する場合は`--side-comparison`とDEVELOPMENT.mdの比較仕様版19手順を使う。生成済み画像の原寸・原画/解析の同一性と公開前SHAを検査する。可視の耳輪郭を変える`--redraw-ear-contour`は利用者の承認を得た場合だけ使う。生成画像と原画の耳をそれぞれ既存DINO/SAMで抽出し、色差だけで耳全体の範囲を代用しない。原画ファイル・目口・許可領域外の画素を保持する検査を通す。輪郭修正版では中立も変わるため、原画全画素固定と呼ばない。通常の非描き直し比較は中立RGBA一致を必須とする。

閉眼の比較は`tools/qwen-eval/build_eye_preview.py`とDEVELOPMENT.mdの手順を使う。同一原画の入力4SHA、原寸で完了した編集、親リグの署名を照合する。まぶたの透過素材だけを抽出し、肌・口などを生成画像ごと貼らない。測定不能を固定曲線で代用しない。原画・他素材を保持して別IDへ公開し、左右別に開き0/0.5/1と連続まばたき・口パクを検証する。個別候補の見た目承認をモデル採用や別原画の合格へ広げない。

## 停止条件

閉眼比較版7ではeye_base/eye_backplateの髪所有画素を除き、局所編集マスクで肌下地を制限する。線の検出は列の局所厚さ・連続横幅・保持率を検査し、curve_detectionの測定値を確認する。傾きや接続した暗い枝を理由に検査を無効化しない。eye_baseには生成済みの肌を使い、検出した閉眼線だけを周囲の肌から補間して別素材に分離する。skin_reconstructionの範囲・暗線除去を確認し、白目用eye_backplateを肌へ変えない。まぶたPNGだけでなく下地の変更も照合し、原画・口・耳など無関係な素材が保持されることを検査する。承認済み旧候補は上書きしない。

抽出版5以降では近傍肌が長い前髪で分断された場合だけ、検出済み肌のRGB勾配を検証付きアフィン平面で補外する。固定色へ降格せず、参照不足や非有限値は停止する。レンダラーは閉眼下地PNG全体を重ねず、原画の目開口内へクリップする。通常の閉眼候補には`--edit-region eyes`の局所編集を使い、マスクSHAとマスク外画素保持を検証する。非限定の旧比較は目視で原寸・構図を確認したものだけ`--allow-unmasked-comparison`で再利用できる。構図が変わった失敗出力をこのオプションで通さない。

閉眼だけを比較するときは通常リグを親にできる。`--base`と`--character`を同じキャラへ向け、耳修正を不要に実行しない。派生候補を親にする場合は原画だけでなく解析署名も一致させる。

入力の前景が空、顔・髪・胴体が識別不能、目口を測定できない、必須画像・座標が欠落、キャンバス寸法が不一致なら明示エラーで止める。固定位置を黙って補って成功扱いしない。

## 再現性と見た目

通常公開参照を持つキャラは、生成中/失敗後も最後の公開済み世代を表示できる。snapshotは世代lease中に逐次読み、素材SHA・PNG寸法・URL・容量上限・終了レコードを確認する。取得失敗や中断時の旧表示保持、lease/Blob解放を検査する。上限値はdisplay.snapshot_*から取得し、縮小や検査省略で通さない。総RAM/VRAM削減、未公開失敗成果物の表示許可、全工程復旧を主張しない。

- 同じ入力の反復で同じ座標・画素が得られるか検査する。
- 合成fixtureでは平行移動・余白変更の影響を検査する。
- 実写だけで完了にせず、あおい（旧女性A）・むぎ・りん・まい・セナ等の別原画を同じ工程で検証する。
- verify-character-visual を読み、閉口、開口、閉眼、小角度変形、透過と原画保持を実ブラウザで比較する。
- テスト成功と目視合格を分けて報告する。未達の画風・入力条件は TASKS と PR 本文へ残す。
- 終了時は自分のプロセスと確認タブを閉じる。停止前に親PIDとコマンドラインを照合する。
