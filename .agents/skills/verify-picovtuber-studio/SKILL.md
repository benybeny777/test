# PicoVTuber配信モードの実画面QA

## 最初に読む

1. `AGENTS.md`と`HANDOFF.md`を読む。
2. `SPEC.md`の第3章（配信モード）を読む。
3. `git status --short`で既存変更を確認し、巻き戻さない。

## 調査する

- `ui/`だけでなく、`cargo xtask build-ui`後の`ui-dist/`とTauri commandの実行経路を追う。
- CSS、DOM、WebGLコンテキスト、キャッシュ版、ウィンドウ寸法を別々に測り、見た目だけから原因を決めない。
- 描画不正はthree-vrmのモデル読み込み、マテリアル、ボーン、morph targetのどこで落ちているかを切り分ける。ブラウザのコンソールだけで判断しない。

## 検証する

- **透過**: 背景が抜けているか。四隅のアルファ値だけで合格にせず、透過市松と配信ソフトの実画面で見る。ハロー、矩形、色面、太い外周影が出ていないこと。
- **描画**: モデルの読み込み、ボーンの姿勢、表情5種と口形6種が実際に形として違うこと。モデル切替でGPUメモリが増え続けないこと（`dispose()`漏れ）。
- **リップシンク**: 実際に日本語を話して口形が追従するか。無音で口が動かないか、話して開くか、ガタつかないか、遅れないか。調整先は`MANUAL.md`の対応表。
- **表情**: 手動プリセットの切替が滑らかか（瞬間切替になっていないか）。自動切替はローカルAIが未導入なら「利用不可」と表示され、クラウドへ落ちないこと。
- **配信出力**: 透過ウィンドウがOBSのウィンドウキャプチャで取り込めるか。使えない出力が理由付きで無効表示になっているか。
- 一時画像・結果は`temp/`だけへ置く。

## 完了条件

原因、修正、機械検査、目視結果をPR本文へ記録する。仕様変更は`SPEC.md`、利用手順変更は`README.md`または`MANUAL.md`へ同期し、未確認項目だけを`docs/TASKS.md`へ残す。`git diff --check`を通してコミット・pushする。

## この環境でできないこと

GPU・マイク・配信ソフトの無いコンテナでは、上の検証はどれも成立しない。**通っていない確認を合格と書かない。** 実機が必要な項目は`docs/TASKS.md`へ着手条件付きで残す。
