# LocalVTuberStudio

PicoAgent向けに、このWindows環境で高品質なキャラクターを同一パイプラインから量産する制作ツールです。ひよりを品質目標に、現在は2D/2.5D方式をブラウザで確認します。完成Live2Dモデル・ひより相当の品質は未達です。Live2D関連の既存PoCは保持し、PicoAgent本体への組み込み・OBS・VRM・macOS／Linux対応は現在行いません。

確認画面は同一キャラの過去候補を混ぜず、むぎ・女性A・PicoAgent実写を各1体だけ表示します。[むぎ](http://127.0.0.1:8791/ui/check.html?character=c_6cbecdd0a13f)と[PicoAgent実写](http://127.0.0.1:8791/ui/check.html?character=c_cfb75db810c3)は通常4工程の最新公開世代、[女性A](http://127.0.0.1:8791/ui/check.html?character=c_df85ec1d7960)は閉眼まで描画できる最新成功版です。女性Aの左耳の差異は判別困難な範囲として利用者承認済みで、見た目の合格版として表示します。旧候補のローカル資産は比較記録として保持し、削除していません。

キャラ切り替え中は旧表示を保ち、新しい素材を読み終えてから切り替えます。読込に失敗した場合は旧表示・選択名・URLを維持し、画面内へ理由を表示します。再生成中の成果物を読む仕組みは改善中です。

口は原画の上下唇を連続変形し、開いた口内へ上歯を表示します。歯はすぼめた口で露出を減らし、閉口原画は変えません。同じ動きの部位は原寸で先に合成して境界の透けを抑えますが、合成用のメインメモリと表情更新時の転送量が増える代償があります。詳細はSPEC.md 4.2と4.10を参照してください。

口の縦開口量は過大な変形を抑えるため従来の40%へ調整しています。閉口の原画・唇・上歯と母音の横幅・すぼめは維持し、全キャラ共通の2軸変形に反映します。

確認画面の「固定口形」で閉口・あ・い・う・え・おを静止比較でき、「口パク動作テスト」で同じ2軸を連続補間します。キャラ切替はURLの`character`へ保存されるため、そのURLを開けば同じ公開キャラを選べます。これはローカルサーバー起動中のPC用リンクで、GitHubだけでは動作しません。

確認画面の口パクは「口パク動作テスト（無音）」で開始します。「待機動作テスト」とは別です。口パク中はボタンが「口パクテストを停止」に変わり、検証中の口形が表示されます。「自動まばたきを開始」は即座に一度まばたきし、完全閉眼を保持してから開き、その後はランダム間隔で繰り返します。動作中は停止ボタンへ変わり、手動の目スライダー操作と中立状態で停止します。「待機動作テスト」は顔・首に加えて肩と胴体へ、全身揺れとして目立たない小さな呼吸変位だけを連動させます。

最新のむぎは、承認済みだった耳・閉眼比較より後に同じ原画から通常4工程を完了した公開世代です。ローカル編集で作ったまつげ・まぶたの線だけを透過素材として取り出し、原画の開いた目から連続して閉じます。原画・口・鼻は閉眼編集で置き換えません。Qwen-Image-Edit-2511の通常局所補完への採用は利用者承認済みです。

スマートフォンから検証済み成果物と旧比較記録を確認する場合は、[キャラクター実画面ギャラリー](docs/CHARACTER_GALLERY.md)を開いてください。

イラスト1枚から、原画の見た目を保った2D/2.5D VTuberキャラクターを作るデスクトップアプリ。**クラウドAPIを一切使わず、すべてローカルで完結する。**

> **現在は2D/2.5D経路への移行中です。** `isolate → decompose → rig2d → complete` で、原画・部位・目口差分と首/襟を分解し、schema_version 3 の `lvs-anime25d-v1` リグを生成します。テクスチャは原寸のまま透過余白だけを切り詰めます。目口の実測座標、口の2軸変形、小角度の動きを実装中です。**ひより相当の品質や機能単位の分割は未達・検証中**です。詳細は [docs/TASKS.md](docs/TASKS.md) T11/T12を参照してください。

ローカルの[原画・描画比較ページ](ui/check.html)は、`sidecar/.venv/Scripts/python.exe tools/preview_server.py` を起動して `http://127.0.0.1:8791/ui/check.html` を開きます。スマホからは信頼できるLAN内で `--lan` を付け、PCのIPアドレスの8791番へ接続します。配信対象は確認画面と検証用キャラだけです。むぎ・女性A・PicoAgent実写のキャラごとの最新成功版を切り替え、左右の閉眼・口の2軸・顔向き・首の傾き・顔の拡大を確認できます。「待機動作テスト」で顔・首と連続した肩・胴体の呼吸動作も確認できます。GitHub上では動的プレビューは動きません。

描画は部位別メッシュへ移行中です。髪・顔・首・胴体・左右腕・未分類部分を分け、表情は顔領域だけを更新します。関節ごとの独立変形と隠れ領域の補完は未完了です。既存Pico形式への変換は現在対象外で、この形式をPico側が扱う想定です。旧単一平面の試作コードは比較用に残しています。

検出できた襟は再生成時に独立描画へ移し、首より手前・顔より奥へ配置します。これは分割時に混ざっていた素材の修正で、隠れた首や肩の復元が完成したという意味ではありません。

袖と手も同じDINO/SAM解析で候補を測り、検出できた可視部分だけを親腕から分けます。未検出・曖昧さは記録し、空素材や固定位置で埋めません。現時点では腕と同じ変位で動き、独立関節や隠れた部分の復元ではありません。

隠れ顔の素材がある候補では、髪が動いて露出した範囲だけ下地を表示します。中立では元の半透明を保ちます。動作時は被覆を求める2回の追加描画と作業用描画メモリが必要です（720×900表示で被覆画像2枚は最大約1.30 MB、別に原寸髪マスク）。

確認画面の「腕を寄せる」は、原画の腕を小角度で内側へ変形する検証操作です。脚へ腕の変形を伝えないよう実測範囲で減衰します。手・袖の隠れた部分を生成する機能ではありません。

Qwen-Image-Edit-2511を通常生成の局所閉眼補完へ採用しました。DINO/SAMは維持し、Layeredは比較のままです。同じ確認サーバーの`http://127.0.0.1:8791/ui/qwen-check.html`で、実験用の原画範囲・生成画像・RGBAレイヤーを並べて確認できます。まだ生成結果がない場合はその旨を表示します。ログ・重み・生のレポートは配信しません。実行条件と手順は[開発手順](docs/DEVELOPMENT.md)を参照してください。

動作確認は`http://127.0.0.1:8791/ui/check.html`で公開中の最新むぎまたはPicoAgent実写を選びます。「顔を拡大」で接合部を見て、「顔左右」「顔上下」「待機動作テスト」で小さな髪の相対移動を確認できます。口は現状で暫定承認されていますが、髪際や別原画の品質は検証中で、全身独立関節や完成Live2Dモデルではありません。生成素材はローカル生成が必要で、Gitへ同梱していません。

## できること

意味解析は利用者承認に基づきGrounding DINO baseを通常の生成経路へ接続しています。`cargo xtask setup grounding`で固定版を取得し、設定画面から保存先と検出閾値を変更できます。Florence-2は比較用のままです。[比較手順](docs/DEVELOPMENT.md#意味解析候補の比較)と、未達の素材分離・品質条件は別に管理します。

目標のパイプラインは「原画/透過検査 → 構造解析 → 素材分離 → 隠れ部分補完 → 部位別リグ → 自動/目視QA」です。現在の4工程には閉眼と隠れ顔・耳の局所補完を実装していますが、追加補完の実画面検証、全身の独立関節や隠れ素材の充足はまだ途中です。目口・首/襟・髪束を独立して動かせる素材を作り、ひよりを品質目標に検証します。[設計と未確定事項](SPEC.md#42-生成パイプライン)を参照してください。

- 手持ちのイラスト1枚から、原画品質を保った2D/2.5Dモデルを自動生成する（実装中）
- 左右のまばたきと、`MouthOpenY × MouthForm` による口形を確認する。原画の合わせ目を追跡し、唇の色・陰影を保つ上下メッシュを連続変形する。まばたきは原画から抽出した上まつげと目のクリップを使用する。確認ページの「口パク動作テスト（無音）」で母音間の動きを比較できる。口内・まつげは品質調整中（6表情の自動生成は未対応）。旧素材は`decompose`から再生成する
- マイク音声をローカル解析してリアルタイムに口を動かす
- 同じ描画コードをブラウザ確認画面で動かす。OBS機能・PicoAgentへの組み込みは現在の対象外

背景生成・ローカルLLM／音声認識の既存機能は保持しますが、今回の制作パイプラインの完成条件や追加開発対象には含めません。

現行方式は実写・女性A・むぎを別原画で検証中です。過去の3D方式での合格を現行2.5Dの合格として扱いません。男性キャラ・後ろ姿・VRM対応は現在の対象外です。品質差は [SPEC.md](SPEC.md) 4.10 に記載します。

## 動かない・やらないこと

- **クラウドAPIを使わない。** ネットワークアクセスはモデルの初回ダウンロードだけ。生成中は完全オフライン
- **動画生成は現在のスコープ外。** 実測していないGPU要件だけを理由に不可能とは判断しません。確認用の動作録画とは別の機能です
- **課金・アカウント登録はない**

## 必要な環境

| 項目 | 要件 |
|---|---|
| OS | Windows 10/11 x64 |
| GPU | 現行の生成経路はCUDA対応NVIDIA GPUを使用。VRAM 8GBの実機で局所補完を検証中。生成要件と完成キャラの描画要件は別です |
| RAM | 最低容量は未確定。局所補完プロセスだけで約16.3 GBの測定例があり、OSや他プロセスの使用量も必要です |
| ディスク | 相当量が必要（実測後に確定） |
| マイク | 音声入力によるリップシンクに必要。無音の動作確認には不要 |

CPUのみの**生成経路は未実装**です。生成時間を実測せずに不可能と判断したものではありません。完成キャラのブラウザ描画には別のWebGL実装を使います。

Python のインストールは不要です（必要なランタイムを同梱します）。

## 開発

Rust、Tauri CLI、WebView2 を用意し、`cargo xtask dev` で起動する。テスト一式は `cargo xtask verify`、Windows向けNSIS配布ビルドは `cargo xtask build`。Node.js は不要。

初回だけ、監査済み固定版を次の順で取得します。取得後の生成・会話・認識はローカルだけで動きます。

```powershell
cargo xtask setup comfy
cargo xtask setup sidecar
cargo xtask setup models
cargo xtask setup grounding
cargo xtask setup completion
cargo xtask setup engines
cargo xtask dev
```

操作画面で入力イラストのパス、表示名、髪・瞳・衣装などの英語タグを登録し、「全工程を実行」を押します。失敗した場合は該当工程だけを選んで再実行できます。入力原本は上書きしません。

## キャラクター生成の処理フロー

キャラクターは次の4工程で作ります。各工程の成果物を `characters/<characterId>/` 以下へ保存してから次へ進むため、失敗した工程だけを再実行できます。

| 工程 | 処理 | 主な成果物 | 次工程での用途 |
|---|---|---|---|
| 入力登録 | PNG/JPEGを取り込み、表示名・人物設定・同一性タグを記録 | `source/input.png`、`character.json` | すべての再生成の起点。入力原本は上書きしない |
| ① `isolate` | 元キャンバスを保持。既存の透過は維持し、不透明入力は背景除去 | `source/isolated.png` | レイヤー分解の入力 |
| ② `decompose` | Grounding DINOで意味領域を検出し、SAM 2.1で原寸マスクと目口差分を生成 | `analysis/analysis.json`、`analysis/masks.npz`、`layers/manifest.json`、`layers/parts/*.png`、`layers/source.psd` | 署名付き解析キャッシュ、2.5D描画部品と確認用PSD |
| ③ `rig2d` | 部位と重なり順を検証し、未補完の基底リグへ変換 | `rig2d-base/rig.json`、`rig2d-base/parts/*.png` | 局所補完の入力。完成扱いしない |
| ④ `complete` | 管理下ComfyUIで原寸の目・髪下地・耳を逐次局所編集し、耳測定と不変検査後に公開 | `rig-current.json`、`rig-generations/g_<ID>/{rig.json,completion.json,parts/*.png}`、各編集/耳解析キャッシュ | 世代固定した共通レンダラー入力。未達は警告/失敗として表示 |

中心資産は`layers/manifest.json`、`layers/parts/`、`rig-current.json`が指す完成リグです。`character.json`で各工程の`pending / running / complete / failed`と理由を管理します。再生成中・失敗後でも公開済みの世代は表示できますが、未公開成果物を完成とは扱いません。

未補完リグは`rig2d-base/`へ保存し、`complete`成功時に不変世代を公開します。閉眼だけだった旧条件の通常4工程はPico実写約19分08秒・むぎ約25分24秒・女性A約19分41秒。閉眼・隠れ顔・耳の3編集を含む現行条件は、むぎとPico実写で通常公開とChrome実動作を確認しました。女性Aは左耳補完が成立せず、失敗を成功へ降格していません。2026年9月7日に利用者が現状品質を今回の完了基準として受け入れ、残る品質改善は追加指示まで保留しました。設定と起動手順は[開発手順](docs/DEVELOPMENT.md#通常の局所補完)、実画像と既知の粗さは[実画面ギャラリー](docs/CHARACTER_GALLERY.md)を参照してください。

```text
characters/<characterId>/
├─ character.json
├─ source/
│  ├─ input.png
│  └─ isolated.png
├─ layers/
│  ├─ source.psd
│  ├─ manifest.json
│  └─ parts/*.png
├─ rig2d-base/             未補完の基底リグ
├─ completion-source/      原寸の局所編集結果と生成署名
│  ├─ edited.png
│  └─ manifest.json
├─ completion-hidden-source/、completion-side-source/
├─ completion-original-ears/、completion-generated-ears/
├─ rig-current.json       公開中/直前世代とSHA
├─ rig-generations/g_<ID>/
│  ├─ rig.json
│  ├─ completion.json
│  └─ parts/*.png
├─ rig-leases/            読込中の世代保持
└─ rig2d/                 既存比較形式のみ保持
```

上流工程を再実行すると、その工程以降だけを無効化します。たとえば②をやり直すと、下流の完了状態を失効させて②から作り直します。旧成果物は新出力の検証・公開が成功するまで保持します。生成に失敗した場合は `character.json` を `failed` にし、壊れた成果物へ黙って進みません。

局所編集の生成結果と素材抽出を別々に保存します。解析コードを直しても原画・実入力画像/マスク・ROI・全推論条件が同一なら3編集を再利用し、抽出だけやり直します。元の生成出自を書き換えず、現在の解析出自とは区別して記録します。SHA不一致や未知形式は明示エラーです。

確認画面は読込中の世代を固定し、検査済み素材が揃ってから表示を切り替えます。切替失敗では旧表示を残します。配信容量とPNG寸法に設定上限があり、超過時に勝手に縮小しません。現在世代・直前世代・読込中世代を保持するため一時的にディスク使用量が増えます。表示全体のRAM/VRAM削減を保証する仕組みではありません。

顔をAIで細かく立体化せず、滑らかな共通頭部へ原画の顔を投影する方式の初回試作は、[顔テンプレート投影の試作結果](docs/TEMPLATE_FACE_PROTOTYPE.md)で正面・斜め・横の実レンダーを確認できます。この試作は方式比較用であり、採用決定や完成品質を示すものではありません。

開発環境の準備、ビルド、実行の手順は [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) を参照してください。

### 再生成とメモリ調整

目口検出を変えた場合は `decompose` 以降、局所閉眼補完の条件だけを変えた場合は `complete` を再実行します。旧リグをそのまま表示せず、原画を保持したまま更新してください。生成欄の「SAM同時処理点数」は既定8です。原画解像度・探索点総数を落とさず、同時処理の量だけを変えます。設定保存後、次回の分解から反映します。
